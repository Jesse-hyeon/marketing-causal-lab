# Criteo·RetailHero 인과추론 실습 구현 명세서

## 1. 프로젝트 목표

첨부한 `ML for Causal Inference` 실습 코드를 기반으로 두 데이터셋에 인과추론 알고리즘을 적용한다.

**핵심 진행 원칙**

- 데이터셋별로 독립적인 Jupyter Notebook(`.ipynb`) 작성
- 각 단계는 **가설 설정 → 코드 실행 → 결과 확인 → 가설 판정** 순서로 구성
- 알고리즘의 원리와 코드 역할을 이해할 수 있도록 단계별 설명 포함
- 기초 인과추론부터 시작해 Causal ML, Uplift Modeling, 의사결정 최적화까지 확장
- 초기 가설과 후속 탐색 가설을 구분하여 기록

## 3. 데이터별 초기 연구 가설

### RetailHero

**RQ. 고객의 과거 구매 이력을 활용하면 프로모션 대상 선정 성능이 개선되는가?**

- H1: 기본 고객 정보만 사용한 모델보다 과거 구매 이력(RFM 등)을 추가한 모델의 Uplift 성능이 높다.
- Treatment: `treatment_flg`
- Outcome: `target`
- 비교: 기본 고객 정보 모델 vs 구매 이력 확장 모델
- 핵심 평가: AUUC, Qini, Uplift@30%

### Criteo

**RQ. 인과효과 기반 타기팅이 무작위 광고 집행보다 효율적인가?**

- H1: 추정 Uplift 상위 30% 고객을 선정하면 동일 인원에 대한 무작위 타기팅보다 추가 방문 효과가 크다.
- Treatment: `treatment`
- Outcome: `visit` (이후 `conversion`으로 확장)
- 비교: 무작위 타기팅 vs Uplift 기반 타기팅
- 핵심 평가: Incremental Visit Rate, Qini, AUUC, Policy Value

두 가설의 최종 판정 기준은 실험 실행 전에 고정한다.

## 4. Notebook 공통 실습 구성

| 단계 | 주요 구현 내용 | 학습 목표 |
|---|---|---|
| 0. Setup | 패키지 설치, 데이터 로드, 실행 환경 고정 | 실습 환경 이해 |
| 1. Hypothesis | RQ·H1·평가 지표·판정 기준 정의 | 검증 가능한 가설 설정 |
| 2. EDA | 데이터 분포, 처치군 비율, 결과 발생률 분석 | 데이터와 실험 구조 이해 |
| 3. Basic Causal Inference | ATE, Outcome Regression, IPW, DoWhy | 기본 인과효과 추정 |
| 4. Causal ML | S-Learner, T-Learner, X-Learner | 고객별 처치 효과 추정 |
| 5. Evaluation | Qini, AUUC, Uplift@K, 신뢰구간 | 추정 모델과 타기팅 성능 평가 |
| 6. Hypothesis Test | 사전 기준에 따라 결과 비교·판정 | 가설 검증과 해석 |
| 7. Advanced | DML, DR-Learner, 추가 특성·정책 실험 | 알고리즘 고도화 |

**구현 순서:** 처음에는 STEP 0~6까지 기초 실습을 완성한다. STEP 7에서는 앞선 결과를 근거로 추가 가설을 세운 뒤 고도화 실험을 진행한다.

## 5. 각 실습 단계의 작성 형식

Notebook의 모든 주요 실습은 다음 형식을 따른다.

**① Hypothesis — 실행 전**

- 무엇을 검증하는가?
- 이 가설을 설정한 이유는?
- 어떤 지표로 판정할 것인가?

**② Implementation — 코드 실행**

- 이번 코드에서 사용하는 알고리즘의 핵심 원리
- 주요 변수·함수·파라미터 설명
- 하나의 분석 목적에 대응하는 실행 코드

**③ Results — 결과 확인**

- 실행 결과 표 또는 시각화
- 수치와 신뢰구간 해석
- 예상과 다른 결과가 나왔는지 확인

**④ Conclusion — 가설 판정**

- 판정: `지지 / 반대 근거 / 판단 보류`
- 판정 이유와 통계적 근거
- 한계점 및 다음 실험에서 확인할 사항

유의하지 않은 결과는 자동으로 가설 기각으로 처리하지 않는다. 비교 지표 차이의 95% 신뢰구간을 기준으로 판정하며, 구간에 0이 포함되면 판단을 보류한다.

새로운 가설이 발견되면 다음 단계에 H2, H3 등으로 추가한다. 기존 가설은 수정하지 않는다.

## 6. 공통 구현 및 평가 규칙

- Train / Validation / Test 데이터를 사전에 분리하고, 최종 Test는 모델 선택에 사용하지 않는다.
- 동일 데이터셋의 알고리즘은 동일한 데이터 분할에서 평가한다.
- 무작위 시드, 패키지 버전, 주요 하이퍼파라미터를 기록한다.
- 모델 비교는 독립 평가 데이터에서 진행하며, 부트스트랩으로 신뢰구간을 계산한다.
- Criteo는 초기 소규모 표본으로 실습하되 원래 처치군 비율을 유지한다. `exposure`는 사전 특성으로 사용하지 않는다.
- RetailHero는 기본 고객 정보부터 시작하고, 구매 이력은 처치 이전 기록만 추가한다.
- ATE와 개별 Uplift 추정값을 구분하여 설명한다.
- 각 코드 셀은 실행 목적을 명확하게 작성하고, 결과를 재현할 수 있도록 구성한다.
